# Taxi v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Taxi addon for WoW Forever in one pass: a summon and portal board with a Summon Guard, Trust and Share ratings, clicker payouts, and a simulation harness that proves all of it without the game.

**Architecture:** The code is split into four layers:
- **Domain** (`Taxi/Domain/`): pure Lua 5.1 state and rules, with no WoW globals.
- **App** (`Taxi/App/`): an `Engine` that wires messages and game events to the domain. It only sees injected `game`, `transport`, `clock` and `rng` objects.
- **Game adapter** (`Taxi/Game/WoW.lua`): translates the WoW API into plain facts and events.
- **UI** (`Taxi/UI/`): Blizzard frames that call Engine methods and listen to Engine events.

A simulated world (`Taxi/Sim/`) runs many Engines on a fake message bus. It powers both the PC tests and the in-game `/taxi sim` mode.

**Tech Stack:** Lua 5.1 (the WoW dialect), busted, luacheck, WSL Ubuntu for running tests, WoW Forever client 1.60.1.

**Spec:** `docs/superpowers/specs/2026-10-17-uber-forever-design.md`

## Global Constraints

- **Lua 5.1 only:** no `goto`, no `//`, no `utf8` library, no integer subtype. `luacheck` runs with `std = "lua51"`.
- **Purity:** `Domain/`, `Comms/`, `App/`, `Sim/` and `Core/` (except `Core/Init.lua`) never touch WoW globals. luacheck enforces this, because those folders are configured with no WoW read-globals.
- **Names in `Core/Config.lua` only:**
  - `NAME = "Taxi"`, `PREFIX = "TaxiFvr"`, `CHANNEL = "TaxiForever"`, `SLASH = "/taxi"`;
  - SavedVariables `TaxiDB` (account) and `TaxiCharDB` (character).
- **Player identity:** a player is their **full two-part name** (first name + surname), compared as an exact trimmed string. First names alone are never compared.
- **Timing:**
  - stand heartbeat 60 s, board TTL 180 s;
  - a stand closes when its owner moves more than 50 yards; the guard radius is 40 yards;
  - death window 120 s.
- **Stand defaults:** 3 traveler seats; clicker share 25% each, so the default split is 50/25/25.
- **Tip presets:** 50s = 5000 copper and 1g = 10000 copper, plus custom.
- **Rating maths:**
  - prior `m = 3.5`, `C = 5`;
  - weights: two-sided 1.0, one-sided 0.3, death 5.0, relayed 0.2, relayed by 3 or more relayers 0.5;
  - "New" below 5 ratings; cap of 500 per warlock per kind; 3 strikes;
  - ratings never expire; `given` is never pruned.
- **Sync:** query cooldown 600 s per warlock, at most 20 replies used, reply jitter 0–5 s, at most 50 records per reply. Relays go one hop only.
- **Wire limits:** at most 255 bytes per addon message, prefix at most 16 characters.
- **Never automated for the player:** the addon never accepts a summon, trade, party invite or portal on the player's behalf.
- **Copy:** all player-facing strings are in English in `Core/Locale.lua`.
- **Plan decisions that refine the spec:**
  1. The wire separator is `^` with `%XX` escaping instead of `|`, because `|` is WoW's chat escape character.
  2. No Ace3 or LibDBIcon. Transport and the minimap button are written by hand. The spec allowed this fallback, and it avoids downloading libraries and the risk of Forever incompatibility.
  3. An `App/` layer is added between Domain and UI, so the simulation can drive full flows.
  4. Two extra messages: `ARRIVED` (traveler, channel) and `CLICK_LEAVE` (clicker, party).
  5. Visible stars are the weighted mean without the prior. The score, used for sorting and guard warnings, includes the prior.
  6. A death counts heavy only when this client heard the victim's own `RIDE_START` and the death is the victim's own report or this client's own observation. `DEATH` reports from third parties count as relayed.
  7. The guard warns (YELLOW) when the warlock's Trust rating is "New" or the score is below 3.0.
  8. A warlock's addon answers queries with its ride logs only. Spec §8.3 also mentions shift logs, but no weight uses them, so they are left out.
  9. Rides are keyed by `traveler.."#"..standId` on both sides; `rideId` is filled in on ACCEPT.

## Review Focus

1. **Two players with the same first name** ("Ana Smith" vs "Ana Jones"): a summon from the wrong one must be RED. → Task 2 (`Names.same`) and Task 9 (guard test `wrong summoner sharing a first name`).
2. **Traveler and warlock using different client languages:** the area check must accept the traveler's localized name for the stand's map, so a German warlock's Ironforge stand shows GREEN for an English traveler. → Task 9 test `localized area name`.
3. **A summon that isn't a Taxi ride:** a summon with no active ride shows YELLOW "Not a Taxi ride", never GREEN or nothing. → Task 9 test `no ride` and Task 15 sim scenario `stranger summon`.
4. **Chat channels full:** joining `TaxiForever` fails. The Engine must emit `STATUS` with the "Leave a chat channel" text and refuse to post stands or requests, not fail silently. → Task 13 test `channel join failure`.
5. **Malformed, truncated or future-version messages,** and chunks that arrive out of order or never complete: these are dropped with no Lua error, and a future version emits one "Update available" status per session. → Task 3 fuzz tests and Task 4 reassembly tests.

### Task 3: Protocol

**Files:**
- Create: `Taxi/Comms/Protocol.lua`
- Test: `tests/comms/protocol_spec.lua`

**Interfaces:**
- Produces:
  - `Protocol.VERSION = 1` and `Protocol.SCHEMAS[type] = { {name, kind}, ... }`, where kind is `"s"` (string), `"n"` (number), `"L"` (list of strings) or `"R"` (list of records using `Protocol.RECORD`).
  - `Protocol.RECORD = {"kind","rater","stars","id","ts","owed","received","pct","other"}`. Record `kind` is `"trust"|"share"|"death"|"ridelog"`. `other` holds the victim for deaths and the traveler for ride logs.
  - `Protocol.encode(type, msgId, fields) -> string`. The wire format is `1^TYPE^msgId^f1^f2...`. `nil` fields become empty. Lists are joined with `,` and records with `;`, with record fields joined by `,`. The characters `% ^ , ; |` and newline are escaped to `%25 %5E %2C %3B %7C %0A`. An unknown type raises `error("unknown type")`.
  - `Protocol.decode(text) -> msg | nil, err, version`. `msg = {v, type, msgId, <field>=value}`. Empty fields decode to nil, and numbers are `tonumber`'d (a bad number gives `"malformed"`). `err` is `"malformed"|"version"|"unknown_type"`; on `"version"`, the third return is the remote version number.
- **Schemas** (field order is part of the wire format):
  - `STAND`: standId s, kind s, faction s, mapID n, x n, y n, wx n, wy n, zone s, subzone s, seatsFree n, clickers n, clickerPct n, portals L, note s
  - `STAND_END`: standId s
  - `REQUEST`: standId s, offer n, level n, dest s
  - `ACCEPT`: rideId s, standId s
  - `DECLINE`: standId s, reason s
  - `CLICK_APPLY`: standId s, askedPct n
  - `CLICK_OFFER`: standId s, offeredPct n
  - `CLICK_OK`: standId s, agreedPct n
  - `CLICK_NO`, `CLICK_LEAVE`: standId s
  - `RIDE_START`, `ARRIVED`: rideId s, warlock s
  - `RIDE_LOG`: rideId s, traveler s
  - `RATING`: kind s, target s, stars n, id s, ts n, owed n, received n, pct n
  - `DEATH`: rideId s, victim s, warlock s, secs n, source s
  - `TIP`, `TIP_ACK`: rideId s, amount n
  - `PORTAL_UP`: dest s
  - `QUERY`: target s
  - `QUERY_R`: target s, records R

### Task 4: Sim clock, bus, and Transport

**Files:**
- Create: `Taxi/Sim/Clock.lua`, `Taxi/Sim/Bus.lua`, `Taxi/Comms/Transport.lua`
- Test: `tests/comms/transport_spec.lua`

**Interfaces:**
- Produces:
  - `Clock.new(start) -> c` with `c:now()`, `c:after(seconds, fn)`, and `c:advance(seconds)`, which runs due timers in time order, including timers scheduled during the advance.
  - `Bus.new{clock, latency=0.1, seed=1} -> bus`:
    - `bus:attach(name, faction, receiveFn) -> backend`, where `receiveFn(prefix, text, dist, sender)`;
    - `bus:setGroup(name, groupId|nil)`, `bus:setLockdown(name, bool)`, `bus:setDropRate(p)`, `bus:sent() -> list of {sender, dist, target, text}` (for assertions).
  - Backend contract, which `Game/WoW.lua` also implements:
    - `backend.send(prefix, text, dist, target) -> code` (0 ok, 3 AddonMessageThrottle, 8 ChannelThrottle, 11 AddOnMessageLockdown, 9 GeneralError);
    - `backend.inLockdown() -> bool`.
    - Bus routing: `CHANNEL` goes to every attached player of the same faction except the sender. `WHISPER` goes to the target. `PARTY`/`RAID` go to the sender's group members. Sender stamping is done by the bus. Throttle is a per-sender token bucket of 10 refilling at 1/s. A text over 255 bytes returns 9.
  - `Transport.new{backend, clock, prefix, onMessage, onVersion} -> t`:
    - `t:send(type, fields, dist, target) -> msgId`;
    - `t:receive(prefix, text, dist, sender)`;
    - `t:pump()`, which the owner calls every 0.2 s;
    - `t:queued() -> n`.
  - Wire chunk format: `msgId:i/n:payload`, with payload slices of at most `Config.CHUNK_PAYLOAD` bytes.
  - `msgId = string.format("%x%04x", now % 65536, counter % 65536)`.
  - Partial reassemblies are dropped after `REASSEMBLY_SECONDS`. Duplicates are ignored by (sender, msgId) for `DEDUPE_SECONDS`.
  - On result 3 or 8, the chunk is requeued at the front and the queue waits 1 s. On result 11 or `inLockdown()`, the queue holds.
  - `onVersion(sender, v)` is called for messages with a newer version.
