# Taxi v1 — controller rulings

Every decision the build controller made on the user's behalf while executing docs/superpowers/plans/2026-10-17-taxi-v1.md, in order, each with its reason and what it costs if wrong. These amend the plan; the spec stays the authority.

- Ruling R1: Taxi.toc lists only files that exist; each task appends its own files in File-map order — helper loads every TOC entry, so listing future files breaks every test — costs nothing if wrong (reorder only).
- Ruling R2: Transport msgId uses math.floor(now) — sim clock is fractional and %x needs an integer — wrong only cosmetically.
- Ruling R3: the ARRIVED handler (sender == traveler) also calls Ratings.addReceipt(db, warlock, rideId, now) — summary count needs receipts and no task wrote them — if wrong, counts are off by unrated rides.
- Ruling R4: ns.WoWClock uses colon methods: now = function() return GetServerTime() end, after = function(_, s, fn) C_Timer.After(s, fn) end — Engine calls clock:after(...) — a mismatch would shift every timer argument in game.
- Ruling R5: World exposes world.clock and world.bus, and World.PLACES adds deadmines = {mapID=291, zone="The Deadmines", subzone="", wx=0, wy=0, levels={15,25}, inInstance=true} — tests use w.clock and the lockdown scenario needs an instance — costs a rename if wrong.
- Ruling R6: Traveler stores a copy of the stand view on the ride at requestRide (ride.stand); the guard uses the live Board view when present, else the snapshot with standChanged = true — a warlock who moves closes the stand before summoning, and the guard must still compare against the agreed spot — if wrong, a moved warlock could produce a guard error instead of RED.
- Ruling R7: T15 fake-death scenario sends RIDE_START, then DEATH{source="self"}, then a REQUEST after ALIVE_GRACE — a self death without a heard ride start is not recorded, so nothing would be undone — scenario-only.
- Ruling R8: no separate git worktree; work happens on feat/taxi-v1 in this session's own clone, which is already isolated — costs nothing.
- Ruling R9: Task 1 Step 1 is already done by the controller — lua5.1 + build tools via apt (user ran sudo), busted 2.3.0 and luacheck 1.2.0 via `luarocks --lua-version=5.1 --local install` (system-wide luarocks install failed copying files). scripts/test.sh must run `eval "$(luarocks --lua-version=5.1 path --bin)"` before busted/luacheck — if wrong, test.sh can't find busted.
- Ruling R10: commit Co-Authored-By trailers follow each subagent's own harness attribution (it names the model that wrote the commit) — more accurate than a fixed line — cosmetic if wrong.
- Ruling R11: Task 2 additions are ratified — Names.same is false for blank names (fail-closed), fromParts treats nil parts as 0 and rejects NaN/inf, format returns "0c" for junk, validateTip returns "zero" for any non-positive-integer amount — all fail closed or display-only — if wrong, a blank name can never match (intended).
- Ruling R12: L and R fields always decode to a table ({} when empty), overriding the brief's "empty fields decode to nil" for list kinds — every honest lock STAND has portals={} and ipairs(nil) in a receive handler would raise on normal traffic — if wrong, consumers just see {} instead of nil.
- Ruling R13: decode stays shape-only; Engine:handle drops a message whose required fields (all non-optional fields per type, defined in one REQUIRED table in App/Engine.lua) are nil, before dispatch — central guard instead of per-handler checks — if wrong, a handler might see a field it expected optional dropped (carry into Task 13 dispatch).
- Ruling R14: receive-side caps — Transport rejects chunk headers with n > 16 (bounds a message to ~3.7 KB); the QUERY_R handler uses at most QUERY_MAX_RECORDS records per reply — bounds hostile replies — carry into Task 4 and Task 13 dispatches.
- Ruling R15: Engine:handle (Task 13) wraps each handler call in pcall and logs the error via ns.Log/print-free sink, so one bad message can't break the receive path or the sim clock — if wrong, handler bugs become quieter (tests must assert no errors were logged).
- Ruling R16: in-game, Transport gets a sub-second clock (now = GetTime) separate from the data clock (GetServerTime) used for timestamps — GetServerTime is whole seconds and Transport's 1 s throttle wait assumes finer resolution — carry into Task 16.
- Ruling R17: when Store.init returns db._newer, Core/Init (Task 16) runs the Engine on a throwaway Store.init(nil) for the session and emits STATUS_UPDATE; the saved TaxiDB is left untouched — a newer db lacks guaranteed tables and must not be mutated — if wrong, an older client works without history for that session.
- Ruling R17a (amends R17): Core/Init reads `local newer = TaxiDB._newer; TaxiDB._newer = nil` right after Store.init, so the saved table stays literally unmutated — Store must set the flag on the saved table per the brief — if wrong, a stale flag could persist (init clears stale flags anyway).
- minor (deferred): Board keyed by standId alone; another sender reusing a standId replaces the entry → handled by Ruling R18.
- Ruling R18: the Engine's STAND handler ignores a STAND whose standId is already on the board under a different owner (until that entry expires), and STAND_END only removes when Names.same(sender, entry.owner); stand ids are generated as `me .. "@" .. now` — prevents hijacking another warlock's listing or faking "stand moved" — carry into Tasks 13/14; if wrong, two honest stands could never collide anyway.
- Ruling R19: the Driver refuses clicker applications from the stand owner or a seated traveler, and travel requests from a seated clicker or the owner — Stand doesn't cross-check roles and double-counting breaks needsRaid — carry into Task 14.
- Ruling R20: the guard's stricter-than-brief fail-closed choices are ratified (nil crewInCombat → RED, standChanged/trustIsNew must be exactly false, negative distance RED, unknown levels YELLOW, non-table facts = no ride); App/Traveler must therefore always pass standChanged and trustIsNew as booleans and crewInCombat as a table — a missing fact can only add warnings — if wrong, extra YELLOW warnings appear.
- minor (deferred): equal junk map IDs (false/0/""/inf) pass the mapID part of the position check → Ruling R21.
- Ruling R21: game adapters and guard-fact builders return nil — never a sentinel like 0, false or "" — for any unknown map ID, distance, level or name — the guard only fails closed on nil/non-finite — if wrong, an attacker-advertised sentinel could match.
- Ruling R22: two-sided weight requires the ride log to name the rater as traveler — else public ride ids give griefers full weight — if wrong, some honest ratings count one-sided.
- Ruling R23: isNew counts only direct records; relayed weight capped per relayer (0.5) and per target total (2.0) via proportional scaling — one modified client must not clear "New" or lift a dangerous warlock over GUARD_LOW_TRUST — costs: long relayed history weighs at most like 2 two-sided ratings.
- Ruling R24: addRelayed rejects relayer == target — a warlock must not relay ratings about itself — none.
- Ruling R25: writes take `now`; ts > now+300 rejected; a rater's one-sided trust ratings for a target count once (newest); prune drops relayed before direct — backdating/future-dating attacks — costs: a rater's repeated one-sided ratings don't accumulate.
- Ruling R26: relayed-vs-relayed conflicts keep the lower stars; no strikes — first-come relays could lock slots — costs: a malicious low relay can drag a relayed copy down (safe direction).
- Ruling R27: strike only when the relayed copy has the same id and ts as the direct record but different stars — re-rating shouldn't strike honest relayers — costs: altered relays of re-rated records aren't punished.
- Ruling R28: Engine accepts an ARRIVED receipt only if the rideId parses as warlock@traveler@ts with Names.same(traveler, sender) and warlock == msg.warlock — bounds count inflation to ids an alt would have to mint itself — display only.
- Ruling R29: a rater's direct share ratings for a target count once (the newest), like one-sided trust (R25); FUTURE_SLACK=300 in Config ratified — one alt could flood backdated share 5★ — costs: a repeat clicker's opinion counts once.
- Ruling R30: Ratings.addDeath persists a whitelisted `source` ("self" | "observed" | "relayed"), and Witness.aliveEvidence reads the stored source (not in-memory ride state) — otherwise a faker who waits out RIDE_MEMORY (or a /reload) keeps a permanent heavy death — costs: one more stored field.
- Ruling R31: Task 11 additions ratified — DEATH_WINDOW also bounds light reports; rideIds of the form driver@traveler@secs must name the report's warlock and victim; victim == warlock refused.
- Ruling R32: at most one heavy death per victim name (persisted check via a victim index); max 3 open rides per victim — a Hardcore character dies once; stops unlimited smears from one identity — residual: one smear per fresh alt (needs a server to close; final-summary note).
- Ruling R33: when arrivedTs is known, a self death report must arrive within DEATH_WINDOW+30 s of arrival — claimed secs alone is untrusted.
- Ruling R34: Store.prune caps db.deaths per target at CAP_PER_KIND (light first, oldest first); Witness uses victim/ride indexes instead of full scans.
- Ruling R35: the Engine records deaths only when game:isHardcore() is true — on other rulesets a death is not permanent, so alive-after-death would wrongly mark liars (carry into Task 13).

- Ruling R37: alive evidence = any Taxi message other than DEATH from that sender; on a dead Hardcore character the Engine sends only its DEATH report and then clears the transport queue and goes silent — so queued messages can't falsely mark a real victim a liar (carry into Task 13).
